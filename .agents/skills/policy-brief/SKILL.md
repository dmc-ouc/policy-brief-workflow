# 政府决策咨询专报工作流

主 Codex 调度真实子 Agent，按阶段验收交付。只搭建、检查配置或学习范文的请求，不启动政策检索、选题或报送稿撰写。不得代写、补写或模拟领导批示，不自动报送，不安装第三方插件。

本目录为可复制的项目工作流。首次使用或用户要求环境检查时，读取 [运行条件与工具](references/runtime.md)，可运行随包 `scripts/doctor.py` 检查文件和可检测的依赖。静态检查不能证明检索、真实子 Agent、字体或渲染能力可用；必须以本次实际工具调用为准。环境检查本身不搜索政策、不选题、不起草；不读取用户尚未授权的材料。

## 入口与状态

- `$policy-brief 选题`：接收研究方向或现实问题、报送层级（市级／省级／国家级）。缺哪项只问哪项，不替用户定层级。城市、省份、部门为可选信息，不因缺这些而额外阻塞入口；未明确地域时不得假称掌握本地问题，选题注明待补地域及证据限制。
- 交付选题单即进入“等待用户定题”，停止，不起草正文。可以推荐，不能替用户选题。
- `$policy-brief 定题`：用户发回选中编号和标题，或明确给出最终题目，才进入深度查证。可直接定题，沿用用户已明确的层级；若层级仍缺，只问层级。区分用户最终题目与仅供讨论的标题。模糊的“继续”不能代替定题。
- 方向、层级或地域范围实质改变时，建立新的范围版本，重新筛选、打开和核查原文；旧证据仅作为线索，不能自动沿用为新范围的有效证据。
- 单独要求学习范文、润色、排版或配置检查，只处理该请求，不自动启动其他阶段。

## 保存与交接

每个新任务创建独立目录 `outputs/policy-brief/YYYYMMDD-HHMMSS-简题/`（按用户时区，重名追加序号）。临时提取、转换、网页和渲染文件放 `work/policy-brief/<task-id>/`。原始材料不改写、不覆盖；可在获授权时留只读副本及哈希。

任务目录内用 `v001/`、`v002/` 等版本保存。首版内各阶段依次新建各自文件；修订时新建下一版本，必要的未改文件原样复制并记来源，禁止覆盖旧稿、旧审核单和证据记录。重试碰到同名文件也分配新版本，不覆盖。版本内保留 `任务卡.md`，内容变更也另存新版本。

任务卡记录：用户原始要求、方向、明确层级、地域与收件方、选题确认原话、当前阶段、输入输出的准确路径、证据与稿件版本、范文/模板使用授权和适用边界、实际润色规范版本、未解决事项，以及真实子 Agent 的调用标识和返回结果。未提供的字段写未提供，不推断。

每次交接明确：角色、任务与停止点、可读材料和授权边界、指定输入版本、新输出路径、必须读取的技能/参考、验收条件。等待子 Agent 实际返回并检查文件存在及内容合格，才能启动下一阶段。不得只以口头“完成”推进。资料可并行搜不同线索，但起草必须等台账；润色等初稿；审核等润色稿；排版等审核处理完毕。

## 真实子 Agent

三个角色配置在项目 `.codex/agents/`：

| 角色 | 任务 | 主要交付 |
|---|---|---|
| policy-research | 官网前置筛选、选题或深度查证、查证退回项 | 00-备选选题单.md；01-证据台账.md |
| policy-writer | 起草，调用 `$policy-brief-polish`，按审核意见修稿 | 02-报送初稿.md；02b-报送润色稿.md |
| policy-reviewer | 独立打开原文复核、复审及排版后内容一致性检查 | 03-审核单.md |

优先用运行时支持的自定义角色启动功能。若工具只有通用 `spawn_agent` 而不能按角色名加载配置，主 Codex 读取对应 TOML，把 `developer_instructions` 与任务卡完整传给真实独立实例，并记录“显式传入角色指令”。这仍是真实委派；不能冒称原生角色已加载。不能在主对话中用三个角色标题扮演子 Agent。

若没有可调用的子 Agent 工具或启动失败，明确说明当前不能执行真实多 Agent 工作流，保存已完成配置和任务状态，停止依赖委派的阶段；不得悄悄改成角色扮演。之后是否单 Agent 处理由用户另行决定。不修改全局模型、权限或安装插件来绕过限制。

## 第 0 步：资料来源前置筛选

资料角色开始选题、深度查证和任何补证前，必须读取 [官网来源准入规则](references/sources.md)。审核角色也独立执行同一门槛。

只接收实际打开原文并核实最终主机名为 `gov.cn` 或以 `.gov.cn` 结尾的网页或文件；域名通过后仍须核发布机关、日期、适用范围和原文实际支持的判断。搜索摘要、打不开的链接、政府站转载媒体稿及非政府来源均不能充当正式证据。无合格原文则待核，不降门槛凑数量。

## 第一阶段：选题

资料角色仅在用户指定层级内筛选：

- 市级：本地能解决的具体堵点；对标同类城市、区县或类似项目，明确对方改了哪一步、由谁负责、本地借鉴条件。
- 省级：多地市共性问题或跨市协调难题；比较条件相近省份及省内不同地市，分清需省级统筹与市级可自行处理的事项。
- 国家级：对照中央政策及相关部委职责，比较多省或国家级试点；找地方权限难解决的制度问题，不用单地个案推全国。

交付 `00-备选选题单.md`，3–5 个实质不同的选题；合格证据不足时少给或不给，说明缺口，不凑题。每题包含：编号、拟题、拟报部门、具体问题与紧迫性、对标对象与可借鉴做法、政府官网原文链接及已核实页码/段落、希望推动的动作、证据缺口。附权限匹配、紧迫性、证据充分度、可落地性比较与推荐理由。拟报部门不确定须标待确认，不冒充已确认收件方。按 [交付字段](references/deliverables.md) 记录最小来源审查结果。

主 Codex 验收并展示选题单后停止，等待用户定题。

## 第二阶段：定题后执行

### 1. 资料角色深入查证

交付 `01-证据台账.md`。每条证据用唯一编号 E001、E002……，不因排序或修稿重编号，不把旧编号指向新来源。按 [交付字段](references/deliverables.md) 记录发布机关、文号或统计口径、日期/时间/适用范围、政策效力、原文链接、定位和可支持判断；区分征求意见、正式发文、试点、实际落地、可核实成效。合格来源间的冲突及判断限制单列；打不开或未准入来源只放任务工作区“线索与核验限制.md”，不能进入正式证据台账。

### 2. 撰写角色起草

验收台账后才交付 `02-报送初稿.md`。开头交代发现什么、为何现在处理、希望收件方推动什么；用一两个已核案例讲清堵点。每条建议写建议由谁牵头、第一步做什么、用什么指标判断成效；建议指标不冒充实际成效，也不自行承诺数值目标或预算。

事实附对应证据编号；分析保留范围与推断强度；建议用建议语气。三者可连贯成文但必须可辨认。权限依据不清时退回资料查证，不替有关部门作承诺。

### 3. 撰写角色调用润色技能

真实 `policy-writer` 读取并调用 `../policy-brief-polish/SKILL.md`，交付 `02b-报送润色稿.md`。使用适用的已学习范文规范；没有范文用通用专报写法。范文只学语言和版式，不贡献事实；不改数字、口径、结论强度、证据对应关系和政策状态。疑点标注退回，不用润色掩盖。

### 4. 审核角色独立复核

以润色稿为准，独立打开政府官网原文，不仅复述台账或信任资料角色结论。核关键事实、数字、政策效力/适用范围、案例成效边界、收件方职责及不宜披露信息。每条建议对应哪个问题、由谁牵头、第一步与衡量指标也在审核范围内。

交付 `03-审核单.md`，逐条采用“原句｜问题｜依据｜改法”，另列严重程度、责任角色、核验动作和处理状态。无问题也列出关键核验清单、实际打开原文、对应定位及限制，不写空泛“全部通过”。

主 Codex 将事实问题退资料角色，将论证/权限/建议设计问题退撰写角色；涉及职责依据时先补证。修改另存新版本，再由审核角色复审。核心依据不足先删减或缩小结论；仍不能成立就移入待确认事项，不放在清稿中当事实。无法访问关键原文时不得判定通过。尚有影响核心结论、权限或披露的未解决问题时停止正式清稿，交用户待确认稿及问题单。等待用户指示不等于核验通过。

### 5. 排版输出与交付人工审定

这是审核后的独立环节，由主 Codex 负责执行和验收，可委派真实撰写角色完成排版。必须读取 [Word 排版规范](references/layout.md) 与 [运行条件与工具](references/runtime.md)，使用当前适用的用户模板和范文学习规则。用户提供明确收件机关模板时优先；没有指定模板时使用随包 [空白报送模板](assets/report-template.docx)。随包通用写法和模板不代表所有机关统一要求，不携带任何原用户范文的读取、上传或公开授权。

生成可编辑 Word，正文为真实段落、标题和必要表格，不把页面截图塞进 Word。分别输出 `04-报送清稿.docx` 与 `04-报送核对稿.docx`；清稿去掉工作用证据编号、批注和交接记录，保留必需的事实限定与有意义的来源说明；核对稿保留证据编号及定位关系。随附最终 `01-证据台账.md`、`03-审核单.md`、`04-待确认事项.md`（无则明确无）及 `04-排版检查单.md`。

排版不得改变已审核内容、数字或结论。可使用随包 `scripts/build_docx.py` 按其支持的输入范围生成成对稿件；它不查证事实、不替代审核。比对清稿/核对稿文本，仅允许预先定义的编号与工作批注差异；若改动内容，回到撰写—润色—审核环节。用本机可用的文档工具渲染并逐页检查，Windows 安装 Word 时可按运行说明使用 `scripts/export_word.ps1` 只读导出。核字体、字号、分页、页码、表格和隐藏修订/批注。字体缺失或无法渲染须明确记录，不能声称已完成版式验收。不得虚构文号、署名、机关标志、印章、批示或审批状态，不自动报送。

最终说明当前版本、尚待人工审定事项和文件链接。人工审定由用户完成；本流程审核、排版均不替代报送单位的审定。
