# 最后环节：正式排版与可编辑 Word 输出

输入为已经独立审核、与证据台账同版本的正文。先完成审核退回问题，再排版；排版不新增事实、不改结论强度、不代写批示。用户单独要求排版已有内容时按授权排版，并说明内容是否经过本流程审核，不因此自动开展研究。

## 格式选择

优先级：用户当前明确要求及收件机关模板 → 同层级同类型已指定模板 → 随包的正式报送稿基线。没有指定模板时使用 [空白模板](../assets/report-template.docx)。通用叙述规则见润色技能的 [style-v001.md](../../policy-brief-polish/references/style-v001.md)。新范文的实际字体和层级须经本次检查后记录，不能把其编辑痕迹、混合行距、偶发缩进、彩色标点、缺失序号或无页码照搬为正式规范。

本项目是“供领导阅示的决策咨询报送稿”，并非自动以党政机关名义制发的法定公文。参照GB/T 9704编排文字与页面，不自动添加红头、文号、密级、发文机关、署名、印章、签发人、成文日期或领导批示。需要的身份要素必须来自用户授权真实值。

## 正式报送稿基线

| 项目 | 本项目默认设置 | 依据与边界 |
|---|---|---|
| 纸张 | A4，210×297mm，纵向、单栏 | 标准5.1 |
| 版心及边距 | 版心156×225mm；上37mm、左28mm，下35mm、右26mm | 上/左及版心见5.2.1；下/右由标称尺寸推算，不是标准独立列项 |
| 主标题 | 二号22pt、小标宋，居中，无额外粗体 | 标准7.3.1为“一般2号小标宋”；随包模板指定方正小标宋简体，接收环境仍须核字体实际可用性 |
| 一级标题 | “一、”，三号16pt黑体 | 标准7.3.3；不额外加粗 |
| 二级标题 | “（一）”，三号16pt楷体 | 标准7.3.3；实际字体是否存在须检查 |
| 三级标题 | “1.”，三号16pt仿宋 | 标准层次；只在正文确有层级时使用，不自动加粗 |
| 四级标题 | “（1）”，三号16pt仿宋 | 标准层次；不为样式表凑层级 |
| 正文 | 三号16pt仿宋，黑色，两端对齐，首行2字 | 标准7.3.3；数字、外文等不因样式处理改变文本 |
| 段落 | 正文段前后0；层次标题首行2字，标题与下段同页 | 项目排版约定；需要模板特有间距时按模板 |
| 行距/网格 | 以固定28pt作为项目初始设置，关闭冲突的旧网格；渲染后按版心和收件模板校准 | 28pt是本项目基线，不是标准强制磅值。标准5.2.3一般每面22行、每行28字，可按情况调整；需严格22行模板时用文档网格实现并实测 |
| 页码 | 四号14pt半角宋体阿拉伯数字，两侧一字线；奇数页右侧空一字、偶数页左侧空一字 | 标准7.5；一字线上缘在版心下边缘以下7mm。使用PAGE域，按实际渲染位置核对，不用空格硬凑或手打每页数字 |

上列用于无更具体收件模板的普通专报正文。明确区分标准条文、工作流排版约定和新范文实测参数；不把参考稿全部属性当成统一标准，也不把参考稿长度当作新稿字数或页数目标。

## 执行步骤

1. 记录当前模板/规范版本、已审核输入路径和校验值。解析正文语义结构，不让Markdown井号或E编号误变为标题。只有确实存在的层级才映射样式，不为了样式表凑四级。
2. 检查字体实际可用性。主标题用Title样式；一级至四级用真正Heading 1—4并正确设置大纲级别，外观服从上表或用户模板。行内导语使用字符样式，不制造空标题段。统一中文字体eastAsia以及数字/西文字体，字号使用明确pt值。
3. 生成新DOCX。用户另提供明确Word模板时基于副本保留模板结构；没有具体模板时使用随包 `assets/report-template.docx`。随包 `scripts/build_docx.py` 用于受支持的 Markdown 正文；先读 [运行说明](runtime.md)，超出输入能力时使用当前可用的文档工具，不能静默丢掉表格等内容。不覆盖范文和已审核稿。旧DOC仅只读转换成新的DOCX，不把重命名后缀当转换。
4. 输出成对稿件：清稿去工作E编号、工作批注、交接记录；核对稿保留E编号及对应关系。正文应一致，必要事实限定不能为清爽而删除。自动比较两者与审核正文，数字、单位、姓名/机构、时间、政策状态和结论强度不得变。
5. 字段和页码按实际页数更新。正文不做截图，不锁定编辑。表格如确需使用，应保持可编辑、跨页表头清楚、不裁切；不得为塞页缩小正文。
6. 在副本上清理不应随稿外发的批注、修订、隐藏文本及作者/修改者/本地路径等元数据，保留用户授权的真实信息；不得对用户原稿自动接受修订。源稿若含未决修订，先明确采用的内容状态，不能静默选一版。
7. 渲染、逐页查看、修复后再次渲染。核缺字/替代字体、标题断行、孤行与孤立标题、页码、表格、页边距、文字溢出、空白页和工作批注残留。不能只检查第一页或只用XML宣称视觉合格。
8. 保存04-排版检查单.md，回传文件与检查结果给主 Codex。正文有实质变化则回撰写—润色—审核，不能以“排版完成”绕过复核。最终交用户人工审定，不自动报送。

## 可用工具与限制

先读取 [运行条件与工具](runtime.md)。环境已有 docx/documents 技能时可使用；未安装这些技能也可使用随包的 Word 生成脚本。需要运行时或文档工具时先发现当前可用路径；若环境提供工作区依赖工具，优先取得 bundled 依赖，不把开发者机器上的绝对路径复制到新机器。不安装第三方插件。

存在可用的文档渲染工具时，按其说明在本地渲染。Windows 且已安装可调用的 Word 时，可用随包 `scripts/export_word.ps1` 创建独立隐藏实例，只读导出本地 PDF，再用可用的 PDF 渲染工具查看每一页。禁用宏，不调用文档内脚本，不写回原件；关闭自己创建的实例，不干预用户窗口。不自动安装办公软件，不上传材料到在线转换服务。其它平台使用本地已有的兼容工具，并记录实际渲染方式及差异。

分享包不包含字体或办公软件，开发环境可用不代表接收环境可用。每次运行检查字体实际存在及渲染结果；未经用户明确接受的字体替换不能宣称严格符合模板。缺字体或无法渲染时，可交付已生成的可编辑文件和明确的未验收事项，不能声称正式排版通过；不以“XML写了字体名”代替实际显示验收。
